Wenn dir Block und Shortcodes nicht reichen, bestimmst du die Ausgabe selbst: mit vier PHP-Funktionen in den Dateien deines Themes, mit überschriebenen Templates – oder mit ganz eigenem Markup aus den rohen Treffern.

Die vier Funktionen

FunktionGibt aus
prstsearch_form( array $options = [] )Das Suchfeld. $options kennt label, placeholder und button_label.
prstsearch_results()Die Treffer der aktuellen Suche mit dem Markup des Plugins.
prstsearch_answer()Den Bereich der KI-Antwort zur aktuellen Suche.
prstsearch_get_results()Gibt nichts aus, sondern liefert die Treffer als Objekt – oder null, wenn die aktuelle Anfrage keine Suche ist.

Beispiel: eine eigene Suchergebnisseite

WordPress zeigt Suchergebnisse mit der Datei search.php deines Themes an. Legst du sie in deinem Child-Theme an, bestimmst du das Aussehen der Ergebnisseite.

wp-content/themes/dein-child-theme/search.php 
<?php get_header(); ?>

<main class="suche">
	<h1>Suche</h1>

	<?php
	// Das Suchfeld, mit eigenen Texten.
	prstsearch_form(
		array(
			'label'        => 'Wonach suchst du?',
			'placeholder'  => 'Land, Ort oder Reiseart',
			'button_label' => 'Finden',
		)
	);

	prstsearch_answer();   // die KI-Antwort, falls der Modus aktiv ist
	prstsearch_results();  // die Trefferliste
	?>
</main>

<?php get_footer(); ?>

Schalte in diesem Fall im Tab Darstellung „KI-Antwort über den Treffern des Themes anzeigen“ aus, sonst erscheint die Antwort doppelt.

Beispiel: ganz eigenes Markup

prstsearch_get_results() liefert ein Objekt der Klasse SearchResults:

Eigenschaft / MethodeInhalt
$results->queryDie Suchanfrage.
$results->hitsDie Treffer der aktuellen Seite, je ein SearchHit.
$results->totalAnzahl der Treffer über alle Seiten.
$results->page, $results->per_pageAktuelle Seite und Treffer pro Seite.
$results->page_count()Anzahl der Seiten.
$results->post_ids()Die IDs der Treffer in ihrer Reihenfolge.
$results->ranking->corrected_queryDie korrigierte Schreibweise, falls ein Tippfehler erkannt wurde, sonst leer.

Ein SearchHit trägt:

Eigenschaft / MethodeInhalt
$hit->post_idDer Inhalt.
$hit->relevanceDie Stufe als Enum; $hit->relevance->value ist high, medium oder low.
$hit->scoreDer Rohwert hinter der Stufe.
$hit->by_keyword, $hit->by_meaning, $hit->by_aiWodurch der Treffer gefunden wurde.
$hit->in_titleOb ein Suchwort im Titel steht.
$hit->is_recommendedOb es ein empfohlener Treffer ist.
$hit->explanation()Ein Satz, warum der Treffer gefunden wurde.
search.php – Treffer als Karten 
<?php
$results = prstsearch_get_results();

if ( null === $results || 0 === $results->total ) {
	echo '<p>Leider nichts gefunden.</p>';
	return;
}

printf( '<p>%d Treffer</p>', $results->total );

echo '<div class="karten">';

foreach ( $results->hits as $hit ) {
	printf(
		'<a class="karte karte--%s" href="%s">%s<h2>%s</h2></a>',
		esc_attr( $hit->relevance->value ),
		esc_url( get_permalink( $hit->post_id ) ),
		get_the_post_thumbnail( $hit->post_id, 'medium' ),
		esc_html( get_the_title( $hit->post_id ) )
	);
}

echo '</div>';
Die normale Schleife geht auch

Bei „Standardsuche von WordPress ersetzen“ stehen die Treffer ohnehin in der Hauptabfrage. Die gewohnte Schleife mit have_posts() und the_post() liefert sie in der richtigen Reihenfolge – nur ohne Relevanz und Begründung.

Templates überschreiben

Das Plugin gibt sein Markup über kleine Dateien aus. Legst du in deinem Theme eine Datei mit demselben Namen an, nimmt das Plugin deine. Ein Update des Plugins überschreibt sie nicht.

  1. Lege in deinem (Child-)Theme den Ordner smart-search an.
  2. Kopiere die gewünschte Datei aus wp-content/plugins/smart-search/templates/ dorthin.
  3. Ändere die Kopie.
DateiGibt ausDaten in $args
search-form.phpDas Suchfeldid, action, query, label, placeholder, button_label, suggestions
results.phpDen Rahmen der Trefferlisteresults, summary, types_html, items_html, has_more, more_url
result.phpEinen einzelnen Trefferitem mit id, title, url, type, excerpt, relevance, relevance_label, score, explanation; dazu show_relevance
type-filter.phpDen Filter nach Inhaltstyptypes, je mit type, label, count, url, is_current
answer.phpDie fertige KI-Antwortparagraphs, sources (je title, url), show_sources
answer-placeholder.phpDen Platzhalter, bis die Antwort geladen istquery, log_token

Beispiel: ein Treffer mit Beitragsbild

wp-content/themes/dein-child-theme/smart-search/result.php 
<?php
defined( 'ABSPATH' ) || exit;

$item = $args['item'];
?>
<li class="prstsearch-result">
	<?php echo get_the_post_thumbnail( $item['id'], 'thumbnail' ); ?>

	<h3 class="prstsearch-result__title">
		<a href="<?php echo esc_url( $item['url'] ); ?>">
			<?php echo esc_html( $item['title'] ); ?>
		</a>
	</h3>

	<p class="prstsearch-result__excerpt">
		<?php echo wp_kses( $item['excerpt'], array( 'mark' => array() ) ); ?>
	</p>
</li>
Drei Dinge, die du beibehalten solltest
  • Maskieren. Titel mit esc_html(), Adressen mit esc_url(). Der Auszug enthält bereits <mark> um die Suchwörter und ist sonst maskiert – gib ihn mit wp_kses() aus, das nur mark erlaubt.
  • Die Attribute data-prstsearch-…. An ihnen findet das Skript des Plugins die Liste, den Link „Weitere Treffer“ und den Filter. Fehlen sie, funktioniert das Nachladen nicht mehr.
  • Die Adresse aus $item['url']. Sie enthält den Sprung zur Textstelle.
